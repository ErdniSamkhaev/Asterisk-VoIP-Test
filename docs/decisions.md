# Проектные решения

## Версия и компоненты

Стенд использует Asterisk 22.11.0 и PJSIP. Для PJSIP_INHERITABLE_HEADER в ветке 22 нужна версия не ниже 22.9.0. Обязательные модули в modules.conf: res_pjsip, chan_pjsip, app_queue, res_pjsip_header_funcs. Автозагрузка разрешает зависимости; RADIUS, HEP и альтернативные реализации voicemail исключены из загрузки.

## Нумерация и контексты

_3XXX покрывает внутренние 3000–3999 и имеет приоритет над общим исходящим _X. Подготовлены 202 телефонных аккаунта: 3000/3001 и обе группы по 100. Сервисные 2000 и 2001 заданы точно; 2001 используется для отдельной проверки маршрута ТП.

from-provider принимает только заданные DID и не включает from-internal. DID 74990000000–74990000009 ведут в IVR, 74990000010 — напрямую в ТП. Специальное условие ТП трактуется как исключение из общего требования IVR.

Внешний маршрут принимает цифры длиной 2–15 и удаляет ведущий +. Другие преобразования номера не заданы. SIPp на 127.0.0.1:5062 моделирует провайдера; identify_by=ip и match с IP/портом ограничивают выбор endpoint. Регистрация и пароль для этого локального транка не используются. Реальный провайдер не подключён.

## КЦ и ТП

Очередь cc: rrmemory, 100 статических участников, ringinuse=no, wrapuptime=3. Правила joinempty/leavewhenempty исключают недоступных участников, но не всех занятых: при занятости можно ожидать ответа. Общий timeout Queue — 60 секунд по правилам приложения.

ТП: внешний скрипт выбирает действующие динамические регистрации 3400–3499 и сохраняет время со списком одним DBPut. Qualify-статус не заменяет факт регистрации. Таймер обновляет список после завершения предыдущего запуска; снимок старше 60 секунд отвергается. RAND выбирает позицию; при отказе выбранного сотрудника повторный выбор не выполняется.

## Доступ и службы

Asterisk работает от asterisk:asterisk; native unit с Type=exec отслеживает процесс. RuntimeDirectory создаёт /run/asterisk, постоянные данные хранятся в /var/lib/asterisk. Готовность телефонии определяется CLI и звонками, а не одним active в systemd.

Секреты root:asterisk 0640 в каталоге local 0750. Конфигурации и программы управляются root. AMI привязан к 127.0.0.1; разрешение system задаёт категорию действий, а не ограничение двумя конкретными запросами. Пароли, AstDB, конфигурации клиентов и исходные SIP-трассы исключены из комплекта.

## Заголовки

Первые значения X-* первого входящего INVITE копируются в наследуемые заголовки и передаются оператору из Queue. Стандартные SIP-поля создаются для нового диалога. Дубли значений одного имени не сохраняются. Передача и изоляция двух параллельных вызовов проверены; retry на другого оператора отдельно не проверялся. Подробности — [headers.md](headers.md).
