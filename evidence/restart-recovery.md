# Восстановление после перезапуска службы

28.10.2026. Перед restart:0activechannels,0activecalls,43callsprocessed. systemctl restart asterisk.service запустил процессPID1736750; native unit /etc/systemd/system/asterisk.service, enabled. systemctl is-enabled asterisk.service tp-sync.timer вернул enabled для обоих.

Первый status снят во время инициализации. Затем CLI подтвердил контакты 3000/3301Avail,3300Unavail. После повторной проверки все три сталиAvail. Причина временной недоступности 3300 не установлена; пользователь открывал телефонный клиент по предложенному сценарию.

Таймер остался active(waiting). Журнал после restart: успешные записи 1793184203|,1793184214|,1793184225|,1793184236| каждые 11 секунд, Finished/Deactivated successfully. Пустой список соответствовал отсутствию ТПпри ролях 3000/3300/3301.

После restart выполнены два одновременных провайдерских вызова DID000 через Queue: SIPp2success0fail, оба оператора ответили, эхо в обоих, заголовки сверены (parallel-queue.md). После возврата MicroSIP на 3401 AstDB показал 1793184808|3401; вызов 3000→2001→3401 прошёл со звуком в обе стороны по подтверждению пользователя.

Итог: восстановление ключевых функций после restart службы проверено. Загрузка системы после reboot не проверялась. При инициализации было сообщение Could not find option minimum_size with type threadpool in module stasis; причина отдельно не исследовалась. Оно не помешало перечисленным фактическим функциональным проверкам.
