# SIP-заголовки в INVITE оператору из очереди

## Два плеча одного вызова

Фильтр пользовательского журнала /var/log/asterisk/lab-headers.log показал входящий INVITE:

```text
INVITE sip:74990000000@127.0.0.1:5060 SIP/2.0
X-Lab-Trace: lab-74990000000-1715025-1
X-Customer-ID: customer-001
```

В исходящем INVITE к 3300 значения совпали:

```text
INVITE sip:3300@PHONE_CONTACT SIP/2.0
X-Lab-Trace: lab-74990000000-1715025-1
X-Customer-ID: customer-001
```

PHONE_CONTACT заменяет реальный адрес и параметры контакта оператора; остальные показанные значения взяты из пользовательского вывода.

## Подтверждение Queue

```text
09:16:37 UTC, 28.10.2026:
Queue("PJSIP/lab-provider-00000039", "cc,,,,60")
09:16:44 UTC, 28.10.2026:
PJSIP/3300-0000003a answered PJSIP/lab-provider-00000039
```

Обе строки в исходном журнале имеют идентификатор C-0000001f. Ранее для этого запуска SIPp подтвердил Successful call 1/Failed call 0, пользователь — слышимость эха, а cleanup — отключение SIP-логирования и удаление временного logger channel.

Передача двух тестовых X-* заголовков в реальный исходящий INVITE оператора именно из Queue подтверждена. Текущая политика копирует первое значение каждого X-* имени; повторные экземпляры и стандартные поля SIP не входят в неё. Одновременные вызовы с разными значениями пока отдельно не проверены.
