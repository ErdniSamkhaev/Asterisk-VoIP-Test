# Входящий DID техподдержки через SIPp

## Сценарий

Пользователь запустил provider-uac.xml с -s 74990000010, источник SIP 127.0.0.1:5062, назначение 127.0.0.1:5060, RTP-эхо на локальном медиа-порту 6000. Предложенный результат — звонок выбранному зарегистрированному сотруднику ТП 3400 либо 3401, ответ и завершение на его клиенте.

## Результат

| Показатель SIPp | Итог |
| --- | --- |
| Созданные исходящие SIPp вызовы | 1 |
| Successful call, cumulative | 1 |
| Failed call, cumulative | 0 |
| INVITE / ACK, отправлены | по 1 |
| 100 / 200 INVITE, получены | по 1 |
| BYE, получен; 200 BYE, отправлен | по 1 |
| Retrans / Timeout / Unexpected-Msg | 0 в показанном сценарии |
| UDP errors send/recv/congestion | 0/0/0 |

Пользователь отдельно подтвердил слышимость эха. Конкретный ответивший номер 3400/3401 в сообщении не назван; отдельная CLI-трасса выбранного номера для этого звонка не запрашивалась. Команда задаёт DID, а сценарий подставляет его в Request-URI через [service]; исходную строку INVITE из файла журнала отдельно пока не показывали.

Лабораторный входящий вызов на DID ТП и звук подтверждены наблюдением пользователя и успешным завершением сценария. Выбор между двумя сотрудниками ранее проверен шестью внутренними вызовами (tp-random-series.md). Остальные 10 городских номеров и заголовки Queue этим тестом не проверены. SIPp завершился, локальный порт можно использовать в следующем сценарии.
